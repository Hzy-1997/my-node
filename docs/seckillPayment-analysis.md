# seckillPayment.js 代码分析文档

## 文件概述

**文件路径**: `routes/managementSystem/payment/seckillPayment.js`  
**功能**: 万人抢票高并发支付模块  
**架构**: Redis + MQ + Worker（完整秒杀架构）  
**版本**: 2.0

---

## 架构设计

```
用户请求(1万并发)
    ↓
抢票接口 (createOrder)
    ↓
┌─────────────────────────────────────────┐
│  1. 参数校验                             │
│  2. 检查用户（Redis缓存）                 │
│  3. 检查重复购买（Redis）                 │
│  4. 初始化Redis库存（如不存在）           │
│  5. 扣减Redis库存（原子操作）             │ ← 5ms完成
│  6. 生成订单号                           │
│  7. 记录购买记录（Redis）                 │
│  8. 发送订单到MQ（异步）                  │ ← 立即返回
│  9. 发送库存同步任务到MQ（异步）          │
└─────────────────────────────────────────┘
    ↓
返回成功（不等待数据库）
    ↓
消息队列 (Bull + Redis)
    ↓
工作进程 (orderWorker.js)
    ↓
同步到数据库（Order表 + Ticket表）
```

## 潜在问题

### 1. ⚠️ 库存过期时间过短

```javascript
await redisService.initializeTicketStock({
  id: goodsId,
  stock: ticket.stock,
  expire: 300, // 5分钟过期
});
```

**问题**:

- 5分钟后Redis库存自动过期
- 如果活动持续时间超过5分钟，库存会丢失
- 新的请求会重新从数据库加载（此时数据库库存可能已被扣减）

**建议**:

```javascript
// 延长过期时间，或永不过期
expire: 86400; // 1天
// 或活动结束后再清理
```

---

### 2. ⚠️ 购买记录过期时间不一致

```javascript
// 初始化库存：5分钟
await redisService.initializeTicketStock({..., expire: 300});

// 购买记录：1小时（但代码写的是60秒）
await redisService.setFun(purchaseKey, {...}, 60); // 实际60秒，注释写1小时
```

**问题**:

- 购买记录60秒就过期，用户可以快速重复购买
- 与注释不符（注释说1小时）

**建议**:

```javascript
// 统一过期时间策略
await redisService.setFun(purchaseKey, {...}, 3600); // 真正1小时
```

---

### 3. ⚠️ 缺少订单超时处理

**问题**:

- 用户抢票成功但不支付，订单一直挂着
- 库存被占用，其他用户无法购买
- 没有自动取消机制

**建议**:

- 添加定时任务，15分钟未支付自动取消
- 恢复库存，删除购买记录

---

### 4. ⚠️ 支付回调处理过于简单

```javascript
exports.notify = async (req, res) => {
    // 只发送队列，没有直接处理
    await queueService.addPaymentJob({...});
    return res.send('success');
};
```

**问题**:

- 如果队列处理失败，订单状态可能不对
- 用户支付成功但订单显示未支付

**建议**:

- 添加补偿机制
- 或关键状态直接更新，不经过队列

---

### 5. ⚠️ 缺少限流保护

**问题**:

- 没有接口限流，可能被恶意刷接口
- 1万并发可能瞬间打垮服务

**建议**:

- 添加限流中间件（如 express-rate-limit）
- 限制单用户请求频率

---

### 6. ⚠️ 缺少库存对账机制

**问题**:

- Redis库存和数据库库存可能不一致
- 没有定时对账修复

**建议**:

- 添加定时任务，每小时对账一次
- 发现差异自动修复
