# 套餐购买流程分析与问题排查文档

## 一、整体架构概览

套餐购买系统采用 **Redis + Lua + Bull MQ** 的高并发架构，核心流程如下：

```
用户请求 → comboRouter → comboPurchaseService → Redis/Lua原子扣减 → Bull MQ异步写库 → 延迟取消任务
```

### 涉及文件

| 文件 | 作用 |
|------|------|
| `routes/managementSystem/comboRouter/combo.js` | 套餐路由控制器（CRUD + 购买入口） |
| `routes/managementSystem/comboRouter/index.js` | 路由注册 |
| `services/comboPurchaseService.js` | 套餐购买服务（继承 BasePurchaseService） |
| `services/basePurchaseService.js` | 基础购买服务（Lua脚本加载、库存扣减/恢复） |
| `services/redisService.js` | Redis连接池与操作封装 |
| `services/queueService.js` | Bull消息队列服务 |
| `workers/orderWorker.js` | 订单工作进程（消费队列、写库、取消回滚） |
| `lua/common/stock_deduct.lua` | 库存原子扣减脚本 |
| `lua/common/stock_refund.lua` | 库存原子恢复脚本 |

## 二、购买套餐完整流程分析

### 2.1 请求入口：`buyCombo`

```
POST /api/managementSystem/comboRouter/buyCombo
```

**请求参数：**

```json
{
  "id": "可选",
  "userId": "用户ID（必填）",
  "packageItemId": "套餐子项ID（必填）",
  "itemType": "类型：1=酒店 2=票务（必填）",
  "num": "购买数量（必填，最大5）",
  "startDate": "开始日期（必填）",
  "endDate": "结束日期（必填）"

```

    │   │

    │   ├─6.5 构建订单数据
    │   ├─6.6 发送MQ异步任务 addOrderJob()

## 三、BUG 分析与问题根因

### 🔴 BUG-1：`refundCombo` 方法不存在（致命错误）

**位置：** `combo.js` 第441行

```javascript
async function rollbackStock(dateRange, packageItemId, roomTypeId, quantity) {
    for (const date of dateRange) {
        await comboPurchaseService.refundCombo({  // ← 此方法不存在！
            packageItemId: packageItemId,
            roomTypeId: roomTypeId,
            quantity: quantity,
            date: date
        });
    }
}
```

**问题：** `ComboPurchaseService` 类中只有 `refundStock(stockKeys, quantity)` 方法，没有 `refundCombo` 方法。当购买过程中某天库存不足需要回滚时，调用 `refundCombo` 会抛出：

```
TypeError: comboPurchaseService.refundCombo is not a function
```

**影响：** 回滚失败 → 已扣减的库存无法恢复 → 库存永久丢失

**修复方案：**

```javascript
async function rollbackStock(dateRange, packageItemId, roomTypeId, quantity) {
    for (const date of dateRange) {
        const stockKeys = [
            `combo:stock:${packageItemId}:${date}`,
            `hotel:roomtype:stock:${roomTypeId}:${date}`
        ];
        await comboPurchaseService.refundStock(stockKeys, quantity);
    }
}
```

### 🔴 BUG-2：`purchaseCombo` 抛异常但 `buyCombo` 检查 `success` 属性（逻辑错误）

**位置：** `comboPurchaseService.js` 第53-56行 vs `combo.js` 第311行

**comboPurchaseService.js 中的逻辑：**
```javascript
const result = await this.deductStock(stockKeys, quantity, userId, orderNo);
if (!result.success) {
    throw new Error(result.message);  // ← 直接抛异常
}
```

**combo.js 中的调用：**
```javascript
purchaseResult = await comboPurchaseService.purchaseCombo({...});
if (!purchaseResult.success) {  // ← 永远不会执行到这里
    await rollbackStock(...);
    return res.json(util.fail(purchaseResult.message));
}
```

**问题：** 当库存不足时，`purchaseCombo` 直接 `throw Error`，不会返回 `{success: false}` 对象。`buyCombo` 的 `if (!purchaseResult.success)` 分支永远不会执行，回滚逻辑被跳过，异常直接被外层 `catch` 捕获，返回通用错误信息"系统错误"。

**影响：**
1. 库存不足时无法正确回滚已扣减的库存
2. 用户看到的是"系统错误"而非"库存不足"等具体提示
3. 购买记录 `purchase:{userId}:{orderNo}` 已写入但无法清理

**修复方案：** `purchaseCombo` 不应抛异常，应返回结果对象：

```javascript
async purchaseCombo({ packageItemId, quantity, userId, orderNo, date, roomTypeId = null }) {
    // ...参数验证...
    const stockKeys = [...];
    const result = await this.deductStock(stockKeys, quantity, userId, orderNo);
    // 不要 throw，直接返回 result
    return result;
}
```

### 🔴 BUG-3：套餐订单取消只处理票务逻辑（致命错误）

**位置：** `orderWorker.js` 第308-360行 `processOrderCancel`

```javascript
async function processOrderCancel(cancelData) {
    const { orderNo, goodsId, userId, count, reason } = cancelData;
    // ...
    // 恢复Redis库存 — 使用的是票务key格式！
    await redisService.incrFun(`ticket:stock:${goodsId}`, count);
    // 恢复数据库库存 — 查询的是 Ticket 表！
    const ticket = await Ticket.findOne({ where: { id: goodsId } });
    // 删除购买记录 — 使用的是票务key格式！
    const orderPurchaseKey = `purchase:${userId}:${goodsId}:${orderNo}`;
}
```

**问题：**
1. 套餐的库存key格式是 `combo:stock:{packageItemId}:{date}`，不是 `ticket:stock:{goodsId}`
2. 套餐库存存在 `PackageDatePrice` 和 `RoomDatePrice` 表，不是 `Ticket` 表
3. 套餐的购买记录key格式是 `purchase:{userId}:{orderNo}`（Lua脚本写入），不是 `purchase:{userId}:{goodsId}:{orderNo}`
4. 取消任务传入的参数是 `packageItemId`、`roomTypeId`、`dateRange`，但函数解构的是 `goodsId`、`count`

**影响：** 套餐超时未支付时，库存完全无法恢复，导致库存永久丢失

**修复方案：** 需要在 `processOrderCancel` 中增加套餐分支：

```javascript
async function processOrderCancel(cancelData) {
    const { orderNo, reason } = cancelData;
    
    const order = await Order.findOne({ where: { orderNumber: orderNo } });
    if (!order || order.orderStatus !== 1) return;
    
    // 判断订单类型
    if (cancelData.packageItemId) {
        // 套餐订单取消
        await rollbackPackageStock(cancelData);
    } else {
        // 票务订单取消（原有逻辑）
        await rollbackTicketStock(cancelData);
    }
}
```

### 🔴 BUG-4：套餐购买未创建主订单记录（数据完整性错误）

**位置：** `orderWorker.js` 第70-111行 `processPackageOrder`

```javascript
async function processPackageOrder(orderData) {
    // 只创建了 PackageOrderDetail，没有创建 Order 主表记录！
    const packageOrderDetail = await PackageOrderDetail.create({...});
    // ...
}
```

**问题：** 票务订单会创建 `Order` 主记录，但套餐订单只创建 `PackageOrderDetail`，不创建 `Order`。这导致：

1. `processOrderCancel` 查询 `Order.findOne({where: {orderNumber}})` 永远找不到套餐订单
2. 支付回调 `processPaymentCallback` 也查 `Order` 表，套餐订单支付成功后无法更新状态
3. 订单列表、订单查询等接口无法展示套餐订单

**影响：** 套餐订单无法被查询、取消、支付确认，整个订单生命周期断裂

**修复方案：** `processPackageOrder` 中必须同时创建 `Order` 记录：

```javascript
async function processPackageOrder(orderData) {
    // 1. 创建主订单
    const order = await Order.create({
        orderNumber: orderInfo.orderNumber,
        memberId: orderInfo.userId,
        userName: orderInfo.userName,
        userPhone: orderInfo.userPhone,
        buyNum: orderInfo.buyNum,
        orderStatus: 1,
        orderAmount: orderInfo.totalAmount,
        // ...
    });
    // 2. 创建套餐订单详情
    const packageOrderDetail = await PackageOrderDetail.create({...});
}
```

### 🟡 BUG-5：Redis 库存1小时过期导致运行时错误

**位置：** `basePurchaseService.js` 第117行

```javascript
async initializeStock(key, stock, expireSeconds = 3600) {
    await this.setFun(key, stock, expireSeconds);  // 默认1小时过期
}
```

**问题：** Redis库存key默认1小时后自动过期。如果用户在库存初始化后超过1小时才购买，或系统运行期间Redis库存key过期：

1. Lua脚本 `stock_deduct.lua` 检查 `redis.call('GET', stockKey)` 返回 `nil`
2. 返回 `{success: false, code: 4001, message: '库存未初始化'}`
3. 用户购买失败，但数据库中实际有库存

**影响：** 间歇性购买失败，特别是低频购买的套餐

**修复方案：**
1. 将过期时间设为套餐有效期的结束日期
2. 或在 `initializeStockIfNeeded` 中对已存在的key也刷新TTL
3. 或在 Lua 脚本中增加自动初始化逻辑

### 🟡 BUG-6：日期比较类型不一致

**位置：** `combo.js` 第279-281行

```javascript
if (combo.endDate < format(new Date(), "yyyy-MM-dd"))
if (format(combo.roomPackage.endDate, "yyyy-MM-dd") < format(new Date(), "yyyy-MM-dd"))
```

**问题：** `combo.endDate` 是 `DATEONLY` 类型，Sequelize 返回的是字符串 `"2025-12-31"`，而 `format(new Date())` 也返回字符串。字符串比较在大多数情况下能工作，但不够健壮。更严重的是，`combo.roomPackage.endDate` 是 `DATE` 类型，`format()` 可能收到 Date 对象或字符串，行为不确定。

**修复方案：** 统一使用 `compareAsc`（已引入但未使用）进行日期比较：

```javascript
const today = new Date();
today.setHours(0, 0, 0, 0);

if (compareAsc(new Date(combo.endDate), today) < 0) {
    return res.json(util.fail("套餐已过期"));
}
```

### 🟡 BUG-8：库存初始化存在竞态条件

**位置：** `combo.js` `initializeStockIfNeeded` 函数

```javascript
let comboStock = await redisService.getFun(comboStockKey, false);
if (!comboStock) {
    // 查数据库 → 写Redis
    await comboPurchaseService.initializeComboStock(combo.id, date, stock);
}
```

**问题：** "先检查后设置"不是原子操作。高并发下多个请求可能同时判断 `!comboStock`，然后重复初始化，导致库存被覆盖重置。

**修复方案：** 使用 Redis `SETNX` 或 Lua 脚本保证原子性初始化：

```javascript
async initializeStockIfNotExists(key, stock, expireSeconds) {
    let client = null;
    try {
        client = await this.pool.getClient();
        const result = await client.set(key, String(stock), 'NX', 'EX', expireSeconds);
        return result === 'OK';
    } finally {
        if (client) await this.pool.releaseClient(client);
    }
}
```

## 五、优化与改进建议

### 5.1 架构层面优化

#### （1）统一订单模型

当前套餐订单和票务订单使用不同的数据结构（套餐用 `PackageOrderDetail`，票务用 `Order`），导致取消、支付等逻辑需要大量分支判断。建议：

- 所有订单统一创建 `Order` 主记录
- `PackageOrderDetail` 作为子表关联 `Order`
- 队列消费者、取消逻辑、支付回调统一通过 `Order` 主表操作

#### （2）统一库存回滚机制

当前存在三套回滚逻辑：
- `combo.js` 的 `rollbackStock()`（有BUG）
- `orderWorker.js` 的 `rollbackPackageStock()`
- `orderWorker.js` 的票务回滚

建议封装统一的 `StockRollbackService`，根据订单类型自动选择正确的回滚策略。

#### （3）库存预热机制

当前是"懒初始化"——购买时才检查并初始化Redis库存。建议：
- 套餐上架/价格规则创建时主动预热Redis
- 定时任务刷新即将过期的库存key
- 避免购买请求中包含数据库查询，降低延迟

### 5.2 代码层面优化

#### （1）消除重复代码

`generateDateRange` 函数在 `combo.js` 和 `basePurchaseService.js` 中各有一份，应统一使用 service 中的版本。

`initializeStockIfNeeded` 在 `combo.js` 和 `comboPurchaseService.js`（`initializeComboStockMultiDate`）中有类似逻辑，应合并。

#### （2）参数校验增强

```javascript
// 当前：只校验存在性
if (!userId || !packageItemId || !itemType || !num || !startDate || !endDate)

// 建议：增加类型和范围校验
if (!userId || !Number.isInteger(userId)) return res.json(util.fail("用户ID无效"))
if (!num || num < 1 || num > 5) return res.json(util.fail("购买数量需在1-5之间"))
if (new Date(startDate) > new Date(endDate)) return res.json(util.fail("日期范围无效"))
```

#### （3）事务保障

`processPackageOrder` 中创建订单和订单详情应在数据库事务中执行：

```javascript
const { sequelize } = require('../../mysql/index');
await sequelize.transaction(async (t) => {
    const order = await Order.create({...}, { transaction: t });
    const detail = await PackageOrderDetail.create({...}, { transaction: t });
});
```

#### （4）幂等性保障

当前购买接口没有幂等性控制，用户快速重复点击可能创建多个订单。建议：
- 基于用户ID + 套餐ID + 日期范围生成幂等key
- 在Redis中设置短期去重标记
- 或在数据库层面增加唯一约束

#### （5）错误处理规范化

当前错误处理混乱：有的返回 `util.fail()`，有的 `throw Error`，有的两者混合。建议：

```javascript
// 定义业务错误类
class BusinessError extends Error {
    constructor(message, code) {
        super(message);
        this.code = code;
    }
}

// 在 buyCombo 中统一处理
try {
    // ...业务逻辑...
} catch (error) {
    if (error instanceof BusinessError) {
        return res.json(util.fail(error.message, { code: error.code }));
    }
    console.error('[buyCombo] 未知错误:', error);
    return res.json(util.fail("系统繁忙，请稍后重试"));
}
```

### 5.3 性能优化

#### （1）批量初始化库存

当前 `initializeStockIfNeeded` 逐天查询数据库并写入Redis，日期范围大时性能差：

```javascript
// 当前：N次数据库查询 + N次Redis写入
for (const date of dateRange) {
    const datePrice = await PackageDatePrice.findOne({where: {packageItemId, date}});
    await comboPurchaseService.initializeComboStock(combo.id, date, stock);
}

// 优化：1次批量查询 + Pipeline写入
const datePrices = await PackageDatePrice.findAll({
    where: { packageItemId: combo.id, date: { [Op.in]: dateRange } }
});
const priceMap = new Map(datePrices.map(dp => [dp.date, dp]));
// 使用 Redis Pipeline 批量写入
```

#### （2）Redis Pipeline

库存初始化和回滚操作应使用 Redis Pipeline 减少网络往返：

```javascript
async batchInitializeStock(items) {
    let client = null;
    try {
        client = await this.pool.getClient();
        const pipeline = client.pipeline();
        for (const { key, stock, expireSeconds } of items) {
            pipeline.set(key, String(stock), 'EX', expireSeconds);
        }
        await pipeline.exec();
    } finally {
        if (client) await this.pool.releaseClient(client);
    }
}
```

#### （3）库存扣减优化

当前逐天扣减，某天失败后需逐天回滚，效率低且风险大。建议使用 Lua 脚本一次性扣减所有日期的库存：

```lua
-- stock_deduct_multi_date.lua
-- KEYS: [combo_stock_date1, hotel_stock_date1, combo_stock_date2, hotel_stock_date2, ...]
-- ARGV: [quantity, userId, orderNo, expireTime]

-- 先检查所有日期的库存
for i, key in ipairs(KEYS) do
    local stock = redis.call('GET', key)
    if not stock or tonumber(stock) < tonumber(ARGV[1]) then
        return cjson.encode({success = false, code = 4002, message = '库存不足'})
    end
end

-- 全部检查通过后一次性扣减
for i, key in ipairs(KEYS) do
    redis.call('DECRBY', key, tonumber(ARGV[1]))
end

return cjson.encode({success = true, code = 200, message = '库存扣减成功'})
```

async purchaseCombo({ packageItemId, quantity, userId, orderNo, date, roomTypeId = null }) {
    if (!packageItemId || !userId || !date) {
        return { success: false, code: 4000, message: '缺少必要参数' };

### 修复3：orderWorker.js processOrderCancel 增加套餐分支

```javascript
async function processOrderCancel(cancelData) {
    const { orderNo, reason } = cancelData;

    try {
        const order = await Order.findOne({ where: { orderNumber: orderNo } });
        
        if (!order) {
            if (cancelData.packageItemId) {
                // 套餐订单可能没有Order记录，直接回滚库存
                await rollbackPackageStock(cancelData);
                return { success: true };
            }
            return { success: true, message: '订单不存在' };
        }

        if (order.orderStatus !== 1) {
            return { success: true, message: '订单已处理，无需取消' };
        }

        if (cancelData.packageItemId) {
            // 套餐订单取消
            await rollbackPackageStock(cancelData);
        } else {
            // 票务订单取消（原有逻辑）
            await redisService.incrFun(`ticket:stock:${cancelData.goodsId}`, cancelData.count);
            const ticket = await Ticket.findOne({ where: { id: cancelData.goodsId } });
            if (ticket) {
                await ticket.increment('remainingStock', { by: cancelData.count });
                await ticket.decrement('soldCount', { by: cancelData.count });
            }
        }

        await Order.update({
            orderStatus: 3,
            cancelReason: reason,
            cancelTime: new Date()
        }, { where: { orderNumber: orderNo } });

        return { success: true };
    } catch (error) {
        console.error(`[CancelWorker] 取消订单失败: ${orderNo}`, error.message);
        throw error;
    }
}
```
