## 1. 背景

原酒店订单模块只有「订单支付」一个入口，缺失以下能力：

1. 酒店订单无法退款（退款接口只识别票务/套餐订单，不识别 `HotelOrder`）
2. 没有酒店核销员管理
3. 没有酒店订单核销动作（前端表格虽展示 `verifyStatus`，但模型里根本没有该字段，也没有核销接口）
4. 支付回调未给酒店订单保存 `alipayTradeNo`，导致即使补上退款逻辑也无法调支付宝退款

本次后端改造一次性补齐上述能力。

## 2. 数据库变更

### 2.1 执行方式

由于旧 migration 文件 `20260712000000-migrate-stock-to-room-inventory.js` 是独立脚本格式（直接调用 `migrate()` 而非导出 `up/down`），`npx sequelize-cli db:migrate` 会在该文件报错 `Could not find migration method: up` 并中断。

因此本次提供两种执行方式：

```bash
# 方式一：独立脚本（推荐，已验证通过）
NODE_ENV=development node migrations/run-hotel-refund-verify-migration.js

# 方式二：sequelize-cli（需先修复旧 migration 文件格式，否则会卡在 20260712 那个文件）
npx sequelize-cli db:migrate --env development
```

脚本幂等，重复执行不会报错（列已存在则跳过）。

## 4. 酒店订单状态流转

### 4.1 订单状态 `status`

| 值  | 含义             | 触发场景                        |
| --- | ---------------- | ------------------------------- |
| 1   | 待支付           | 下单 `hotelRoomBook` 创建       |
| 2   | 待核销（已支付） | 支付宝回调 `orderWorker` 置为 2 |
| 3   | 已取消           | 超时未支付 / 手动取消           |
| 4   | 已完成           | 核销成功后置为 4                |
| 5   | 已退款           | 退款成功后置为 5                |

### 4.2 核销状态 `verifyStatus`

| 值  | 含义                           |
| --- | ------------------------------ |
| 1   | 待核销                         |
| 2   | 已核销                         |
| 3   | 已取消（退款或取消时联动置 3） |

### 4.3 状态流转图

```
下单            支付成功          核销
[1 待支付] ──→ [2 待核销] ──→ [4 已完成]
   │              │
   │ 超时未支付    │ 申请退款
   ↓              ↓
[3 已取消]    [5 已退款]
              verifyStatus=3
```

## 6. 接口详情

### 6.1 酒店核销员操作 `POST /api/hotel/hotelWriteOffOperate`

复用票务核销员表 `write_offs`，通过 `type=2` 区分酒店核销员。

**请求体（application/json）**

| 字段   | 类型   | 必填               | 说明                           |
| ------ | ------ | ------------------ | ------------------------------ |
| action | string | 是                 | `create` / `update` / `delete` |
| phone  | string | 是                 | 核销员手机号                   |
| id     | int    | update/delete 必填 | 核销员记录 id                  |
| name   | string | create 必填        | 核销员姓名                     |
| status | int    | 否                 | 1-启用, 2-停用                 |

**示例**

```json
// 创建
{ "action": "create", "name": "张三", "phone": "13800138000", "status": 1 }

// 编辑
{ "action": "update", "id": 10, "name": "张三", "phone": "13800138000", "status": 2 }

// 删除
{ "action": "delete", "id": 10 }
```

**返回**

```json
{ "code": 200, "message": "创建成功" }
```

**逻辑说明**

- `create`：校验同手机号 + type=2 唯一；操作人从 token 解析写入 `operator` 字段
- `update`：强制 `type=2`，防止误改票务核销员
- `delete`：`where: { id, type: 2 }`，只删酒店核销员

## 7. 酒店退款阶梯扣款规则

### 7.1 阶梯规则表

按入住日（`checkInDate`）与今天（`T`）的自然日差值 `diffDays` 计算：

| diffDays | 场景                  | 退款比例 | 扣款比例 | 规则描述 | 普通退款 |
| -------- | --------------------- | -------- | -------- | -------- | -------- |
| >= 5     | 入住前5天及以上       | 100%     | 0%       | 免费取消 | ✅ 允许  |
| == 4     | 入住前4天             | 70%      | 30%      | 扣30%    | ✅ 允许  |
| == 3     | 入住前3天             | 50%      | 50%      | 扣50%    | ✅ 允许  |
| == 2     | 入住前2天             | 20%      | 80%      | 扣80%    | ✅ 允许  |
| <= 1     | 入住前1天/当天/已过期 | 0%       | 100%     | 不可退款 | ❌ 拒绝  |

> `diffDays` 计算方式：`Math.round((checkIn(归零时分秒) - today(归零时分秒)) / 86400000)`

### 7.2 强制退款（用户投诉场景）

当 `diffDays <= 1` 普通退款被拒绝时，可通过 `forceRefund=true` 走强制退款通道：

| 维度       | 普通退款                     | 强制退款                                                        |
| ---------- | ---------------------------- | --------------------------------------------------------------- |
| 触发条件   | 用户/后台常规退款            | 用户投诉，后台审核后强制退                                      |
| 日期校验   | 按阶梯规则扣款               | 跳过日期校验                                                    |
| 退款金额   | 按比例计算（如 70%）         | **全额退款**（扣款 0）                                          |
| refundType | 1                            | 2                                                               |
| 需要参数   | orderNumber + adminId/userID | orderNumber + adminId + `forceRefund=true` + `reason`(投诉原因) |

### 7.3 退款接口 `POST /api/alipay/refund`

原接口只查 `Order` 和 `PackageOrderDetail`，现扩展为三级查找：

```
Order.findOne → 没找到 → PackageOrderDetail.findOne → 没找到 → HotelOrder.findOne
```

**请求体**

| 字段        | 类型    | 必填             | 说明                                 |
| ----------- | ------- | ---------------- | ------------------------------------ |
| orderNumber | string  | 是               | 订单号                               |
| adminId     | int     | 二选一           | 管理员 id（后台退款）                |
| userID      | int     | 二选一           | 用户 id（用户自助退款）              |
| forceRefund | boolean | 否               | 是否强制退款（投诉场景），默认 false |
| reason      | string  | 强制退款时建议传 | 投诉/强制退款原因                    |

**示例**

```json
// 普通退款（按阶梯扣款）
{ "orderNumber": "ORDHD20260721xxx", "adminId": 1 }

// 强制退款（投诉全额退）
{ "orderNumber": "ORDHD20260721xxx", "adminId": 1, "forceRefund": true, "reason": "用户投诉房间卫生问题" }
```

**酒店订单退款流程**

1. 查询订单 → 识别为 HotelOrder
2. 校验订单状态（status=2 已支付 或 status=4 已完成）
3. 若 `forceRefund=true`：全额退款，`refundRuleDesc = "强制退款-投诉:{reason}"`
4. 若普通退款：调 `calcHotelRefundAmount(checkInDate, totalPrice)`
   - `canRefund=false` → 返回失败：`当前不可退款（入住前X天-不可退款）。如需退款可使用强制退款`
   - `canRefund=true` → 按比例计算退款金额和扣款金额
5. 调支付宝 `alipay.trade.refund`，`refund_amount` = 实际退款金额（已扣手续费），`refund_reason` = 规则描述
6. 更新 `HotelOrder`：status=5, verifyStatus=3, refundAmount=实际退款金额
7. 创建 `RefundOrder` 记录：
   - `refundReason` = "后台操作退款-入住前4天-扣30%"（拼接规则描述）
   - `refundType` = 2（强制退款）或 1（正常退款）
   - `orderType` = 3（酒店）
8. 异步恢复酒店库存（Redis + DB RoomInventory）

**酒店订单与票务/套餐退款差异对照**

| 维度              | 票务/套餐                                                    | 酒店                           |
| ----------------- | ------------------------------------------------------------ | ------------------------------ |
| 订单状态字段      | `orderStatus`                                                | `status`                       |
| 退款金额字段      | `orderAmount`（全额退）                                      | `totalPrice` → 按阶梯计算      |
| 可退款状态        | 2, 4                                                         | 2, 4                           |
| 退款后状态        | orderStatus=5                                                | status=5                       |
| 退款单 orderType  | 1(票务)/2(套餐)                                              | 3(酒店)                        |
| 退款单 refundType | 1                                                            | 1(正常) 或 2(强制)             |
| 库存恢复          | `restoreStockAfterRefund` / `restorePackageStockAfterRefund` | `restoreHotelStockAfterRefund` |

**成功返回**

```json
{
  "code": 200,
  "message": "退款成功",
  "data": {
    "orderNumber": "ORDHD20260721xxx",
    "refundNo": "RFD20260721xxx",
    "refundAmount": 840.0,
    "deductionAmount": 360.0,
    "refundRule": "入住前4天-扣30%",
    "isForceRefund": false,
    "restoredStock": 2
  }
}
```

**失败场景**

| 场景              | 返回 message                                               |
| ----------------- | ---------------------------------------------------------- |
| 订单不存在        | 订单不存在                                                 |
| 订单状态不可退款  | 当前订单状态不可退款                                       |
| 入住前1天普通退款 | 当前不可退款（入住前1天-不可退款）。如需退款可使用强制退款 |
| 支付宝退款失败    | 退款失败                                                   |

**酒店库存恢复逻辑**（`restoreHotelStockAfterRefund`，异步执行，失败不影响退款结果）

1. 调 `hotelPurchaseService.refundHotel` 恢复 Redis 库存（按 `hotel:roomtype:stock:{roomTypeId}:{date}` key）
2. 同步 DB `RoomInventory`：`availableStock += roomCount`，`soldStock -= roomCount`，按入住晚数逐日恢复

## 8. 支付回调修复

`workers/orderWorker.js` 酒店订单支付成功分支，原代码：

```js
await HotelOrder.update(
  {
    status: 2,
    paymentTime: notifyData.gmt_payment,
  },
  { where: { orderNumber: out_trade_no } },
);
```

修复后：

```js
await HotelOrder.update(
  {
    status: 2,
    verifyStatus: 1,
    alipayTradeNo: notifyData.trade_no, // 新增：退款必需
    paymentTime: notifyData.gmt_payment,
  },
  { where: { orderNumber: out_trade_no } },
);
```

**修复原因**：原代码未保存支付宝交易号 `alipayTradeNo`，导致退款时调 `alipay.trade.refund` 必传的 `trade_no` 为 null，支付宝会拒绝退款。
