# 订阅提醒定时任务设计文档

> 范围：用户订阅提醒的"定时扫表 → 发送提醒"环节。
> 订阅入口（`routes/mobileApp/subscribeRouter/reminder.js`）与 `reminder` 表已完成，本文档只设计定时任务部分。
> 渠道分三期：**一期微信小程序订阅消息（本次实施）**，二期站内消息表，三期短信。

---

## 一、背景与现状

### 1.1 业务链路

```
前端弹授权：wx.requestSubscribeMessage，用户同意（一次性授权 = 允许发送一条）
    │
    ▼
用户订阅（已完成）
    │  POST /mobileApp/subscribe/reminder
    │  写入 reminder 表，status=1 待发送
    ▼
定时扫表（本文档）
    │  cron 周期扫描 status=1 且 reminderTime <= now 的记录
    ▼
发送提醒（一期：微信小程序订阅消息，见第四章）
    │  发送成功 → status=2 已发送
    │  发送失败 → status=3 失败
```

**关键前提**：调用订阅接口存表的数据都是用户**已同意授权**的（前端先弹授权、同意后才存表），后端发送时无需也无法再校验授权状态，直接调微信发送接口消耗这次授权即可。

### 1.2 已有资产盘点

| 资产              | 位置                                                               | 状态                                                                                                                       |
| ----------------- | ------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------- |
| Reminder 模型     | `models/reminderModel/index.js`                                    | 已建，`sequelize.define('reminder')` 未指定 tableName，实际表名为 `reminders`（Sequelize 默认复数，写 SQL 前先核对）       |
| 订阅接口          | `routes/mobileApp/subscribeRouter/reminder.js`                     | 已建，写库 status=1                                                                                                        |
| 定时任务基建      | `tasks/orderExpireTask.js` + `app.js` 的 `initializeCronJobs()`    | 已有成熟范式：node-cron 调度、条件更新保幂等、失败只记日志不中断                                                           |
| 微信小程序配置    | `config/index.js`                                                  | `APP_ID` / `ACCESS_SECRET` 环境变量已有，直接复用                                                                          |
| access_token 管理 | `routes/mobileApp/appLoginRouter/login.js` 的 `getWxAccessToken()` | 已实现：Redis 缓存（`accessToken:wx:{APP_ID}`，存 `expires_in-200` 秒）+ 单飞 Promise 防并发。**未导出，复用需加一行导出** |

## 二、总体方案

新增 `tasks/reminderTask.js`，复用项目现有定时任务模式，在 `app.js` 的 `initializeCronJobs()` 中注册一行。

```
cron 每30秒触发
    │
    ▼
查询：status=1 AND reminderTime <= now（limit 100）
    │
    ▼ 逐条处理
① 抢占：条件更新 status 1→2，同时写 sendTime
   （where 带 status=1，更新行数=0 → 已被处理，跳过）
    │
    ▼ 抢占成功
② 调用发送渠道 sendReminder(item) —— 一期即微信订阅消息
   成功 → 完成（状态已在①落库）
   失败 → 条件更新置 status=3
```

**关键设计：先抢占、后发送。**
与 `orderExpireTask` 的"先条件更新、再执行副作用"同一套路：

- 幂等：同一记录被并发扫描/多实例（pm2 cluster）同时捞到时，只有条件更新成功的那一方会真正发送；
- 自愈：服务重启/宕机期间错过的提醒，因扫描条件是 `reminderTime <= now` 而非精确等于，恢复后下一轮自动补发，无需额外补偿逻辑。

---

## 三、核心规则

| 规则     | 说明                                                                                                    |
| -------- | ------------------------------------------------------------------------------------------------------- |
| 扫描频率 | `*/30 * * * * *`（每30秒，与 orderExpireTask 一致）。提醒精度损失最多30秒，对分钟级提醒场景可接受       |
| 扫描条件 | `status = 1 AND reminderTime <= now`，`limit 100` 防大结果集。若积压超过100条，下一轮30秒后自动继续消化 |
| 状态流转 | 1待发送 → 2已发送（抢占成功）或 3失败（发送异常）                                                       |
| 失败处理 | 基础版：失败置3，人工排查后可手动 `UPDATE status=1` 重发。重试机制见第六章                              |
| 超期提醒 | 可选规则：宕机恢复后，reminderTime 已远过（如超过 projectStartTime）的提醒可不再补发，规则见第六章      |

## 四、发送渠道（分三期实施）

三个渠道均要做，渠道分派收敛在 `sendReminder(item)` 单一入口，后续分期只在该入口内追加分支，扫表主流程不动。

| 阶段         | 渠道                 | 依赖现状                                     |
| ------------ | -------------------- | -------------------------------------------- |
| 一期（本次） | 微信小程序订阅消息   | 配置、token 管理、openid 均已具备，见 4.1    |
| 二期         | 站内消息表 + APP轮询 | 新建 message 表 + 查询接口，见 4.2           |
| 三期         | 阿里云短信           | SMS 密钥已有；手机号加密存储需先解密，见 4.3 |

### 4.1 一期：微信小程序订阅消息

#### 授权模型（一次授权一条）

微信订阅消息是"一次授权一次发送"：用户在每条提醒存表前，前端须先弹授权并得到同意。本项目约定 **存表 = 已授权**，一条 `reminder` 记录恰好一次发送，与授权次数一一对应：

```
前端：wx.requestSubscribeMessage({ tmplIds: [模板ID] })   ← 用户点"允许"
  ↓ 同意后
前端：POST /mobileApp/subscribe/reminder 存表（status=1）
  ↓ reminderTime 到点
定时任务：POST subscribe/send 发送（消耗这次授权）
  ↓
status=2 已发送 / 3 失败
```

若同一项目要多次提醒（如提前1天 + 提前2小时各一条），需存多条 reminder 记录、前端对应请求多次授权。

#### 现有资产复用（均已确认可用）

| 资产                       | 复用方式                                                                                                                                                  |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `APP_ID` / `ACCESS_SECRET` | `config/index.js` 环境变量已有                                                                                                                            |
| `getWxAccessToken()`       | `login.js` 内已实现（Redis 缓存 + 单飞防并发）。该文件是逐个 `exports.xxx` 风格，**末尾追加一行 `exports.getWxAccessToken = getWxAccessToken;` 即可复用** |
| 用户 openid                | `Member.findOne({ where: { id: userId } }).openld`                                                                                                        |
| 发送接口                   | `POST https://api.weixin.qq.com/cgi-bin/message/subscribe/send?access_token=xxx`                                                                          |

#### 需新增配置（一期仅此三项前置）

1. 小程序后台申请**订阅消息模板**，拿到 `template_id`；
2. `.env` 加 `WX_REMINDER_TEMPLATE_ID`，`config/index.js` 微信段加一行读取；
3. `login.js` 导出 `getWxAccessToken`（一行）。

#### 模板字段映射（以实际申请到的模板为准，下为占位示例）

| 模板字段（示例）      | 取值                    | 微信格式要求                                       |
| --------------------- | ----------------------- | -------------------------------------------------- |
| thing1（提醒内容）    | `item.reminderContent`  | thing ≤ 20字符，超长截断                           |
| time2（项目开始时间） | `item.projectStartTime` | time 类型须为 `yyyy年M月d日 HH:mm` 或 `HH:mm` 格式 |
| page                  | 跳转页面                | 如 `pages/index/index`，按业务调整                 |

#### 发送结果处理（errcode）

| errcode       | 含义                      | 处理                                                                            |
| ------------- | ------------------------- | ------------------------------------------------------------------------------- |
| 0             | 成功                      | 状态已在抢占时置2                                                               |
| 43101         | 用户未授权/授权额度已消耗 | 置3，**不重试**（授权一次性，重试无意义）；多为前端漏弹授权或额度已用，日志排查 |
| 40003         | openid 无效               | 置3，不重试，记录日志                                                           |
| 40001 / 42001 | access_token 无效/过期    | 清 Redis 缓存重取 token，**重发一次**；再失败置3                                |
| 其他          | 网络/参数等               | 置3（后续可启用第六章重试机制）                                                 |

### 4.2 二期：站内消息表 + APP 轮询

```sql
CREATE TABLE `messages` (
    `id` INT AUTO_INCREMENT PRIMARY KEY,
    `userId` INT NOT NULL COMMENT '接收用户',
    `title` VARCHAR(100) NOT NULL COMMENT '标题',
    `content` VARCHAR(500) COMMENT '内容',
    `isRead` TINYINT NOT NULL DEFAULT 0 COMMENT '0未读 1已读',
    `createdAt` DATETIME,
    `updatedAt` DATETIME
) COMMENT '站内消息表';
```

配套一个 GET 接口（未读数 + 分页列表 + 标记已读），APP 端进入消息中心/启动时轮询。二期上线后 `sendReminder` 内追加分支：写 `messages` 表，可与微信渠道并送（由 `reminderType` 约定决定单发还是并送）。

### 4.3 三期：阿里云短信

- `config/index.js` 已有 `SMS_ACCESS_KEY_ID` / `SMS_ACCESS_KEY_SECRET` / `SMS_SIGN_NAME`；
- `Member.phone` 为加密存储（`salt:iv:encrypted` 格式，项目统一加密规范），发送前需 `util.decrypt`；
- SDK 用 `@alicloud/dysmsapi20170525`，短信模板+签名需在阿里云控制台报备；
- 按条计费，建议仅高价值场景（出行类提醒）启用，与微信渠道互补。

## 五、实现设计

### 5.1 新增 `tasks/reminderTask.js`

```js
/**
 * 订阅提醒定时任务
 *
 * 每30秒扫描 reminder 表：status=1 且 reminderTime <= now 的记录，
 * 先条件更新抢占（1→2，幂等，多实例安全），再调用发送渠道。
 * 发送失败置 status=3，人工排查后可手动重置为1重发。
 *
 * 一期渠道：微信小程序订阅消息（存表即视为用户已授权，一次授权一条）。
 * 启动：由 app.js 的 initializeCronJobs() 注册，随主进程运行。
 */
const cron = require("node-cron");
const axios = require("axios");
const { Op } = require("sequelize");
const { Reminder, Member } = require("../models/Summary");
const {
  getWxAccessToken,
} = require("../routes/mobileApp/appLoginRouter/login");
const redisService = require("../services/redisService");
const { APP_ID, WX_REMINDER_TEMPLATE_ID } = require("../config/index");

// 微信订阅消息 time 字段格式：2026年11月18日 10:00
function formatWxTime(date) {
  const d = new Date(date);
  const pad = (n) => String(n).padStart(2, "0");
  return `${d.getFullYear()}年${d.getMonth() + 1}月${d.getDate()}日 ${pad(d.getHours())}:${pad(d.getMinutes())}`;
}

/**
 * 发送渠道入口 —— 渠道分派收敛于此，二期站内信/三期短信在此追加分支
 * 抛出异常 → 主流程置 status=3（43101 未授权等错误同样走此路径，不重试）
 */
async function sendReminder(item) {
  const member = await Member.findOne({
    where: { id: item.userId },
    attributes: ["openld"], // 历史拼写笔误，存的就是 openid，照常取值
  });
  if (!member || !member.openld) throw new Error("用户 openid 缺失");

  const payload = {
    touser: member.openld,
    template_id: WX_REMINDER_TEMPLATE_ID,
    page: "pages/index/index", // 点击提醒跳转的小程序页面，按业务调整
    data: {
      // 字段名以小程序后台实际申请的模板为准（示例：thing1 提醒内容 / time2 项目开始时间）
      thing1: { value: String(item.reminderContent).slice(0, 20) },
      time2: { value: formatWxTime(item.projectStartTime) },
    },
  };

  const send = (token) =>
    axios.post(
      `https://api.weixin.qq.com/cgi-bin/message/subscribe/send?access_token=${token}`,
      payload,
    );

  let { data } = await send(await getWxAccessToken());

  // access_token 失效（40001/42001）：清缓存重取，重发一次
  if (data.errcode === 40001 || data.errcode === 42001) {
    await redisService.delFun(`accessToken:wx:${APP_ID}`).catch(() => {});
    ({ data } = await send(await getWxAccessToken()));
  }

  if (data.errcode !== 0) {
    throw new Error(`微信订阅消息发送失败: ${data.errcode} ${data.errmsg}`);
  }
}

async function scanAndSendReminders() {
  const now = new Date();

  // 只捞待发送且提醒时间已到的，limit 100 防大结果集
  const due = await Reminder.findAll({
    where: {
      status: 1,
      reminderTime: { [Op.lte]: now },
    },
    limit: 100,
  });

  for (const item of due) {
    try {
      // ① 抢占：条件更新保证幂等，更新行数=0 说明已被处理，跳过
      const [claimed] = await Reminder.update(
        { status: 2 },
        { where: { id: item.id, status: 1 } },
      );
      if (claimed === 0) continue;

      // ② 发送：失败回置 status=3
      try {
        await sendReminder(item);
      } catch (error) {
        await Reminder.update(
          { status: 3 },
          { where: { id: item.id, status: 2 } },
        );
        console.error(`[Reminder] 发送失败: id=${item.id}`, error.message);
      }
    } catch (error) {
      console.error(`[Reminder] 处理异常: id=${item.id}`, error.message);
    }
  }
}

function start() {
  // 每30秒扫描一次，与 orderExpireTask 保持一致
  cron.schedule("*/30 * * * * *", async () => {
    await scanAndSendReminders();
  });
  console.log("[Reminder] 订阅提醒定时任务已启动（每30秒扫描）");
}

module.exports = { start, scanAndSendReminders };
```

## 六、通用增强（按需启用，不建议一步到位）

### 6.1 失败自动重试

发送失败不直接置3，而是 `retryCount+1`，未超上限（如3次）时回置 `status=1` 等下一轮重扫；超限置3。需先执行 5.4 的 `retryCount` 字段 SQL。
注意：43101（未授权）不应参与重试，重试也无意义，应在 `sendReminder` 抛错前识别并直接置3。

### 6.2 超期不补发规则

服务长时间宕机恢复后，`reminderTime` 已远过（如超过 `projectStartTime`）的提醒再发已无意义，可在扫描时直接置失效（新增状态4-已失效，或复用置3）：

```js
// 项目都开始了才补发的提醒，直接置失效
await Reminder.update(
  { status: 3 },
  { where: { status: 1, projectStartTime: { [Op.lt]: now } } },
);
```

## 七、测试验证

1. **前置配置**：`.env` 已填 `WX_REMINDER_TEMPLATE_ID`、`login.js` 已导出 `getWxAccessToken`、`config/index.js` 已加读取；
2. **手工造数**（userId 必须是真实登录过的 Member，否则没有 openid）：

```sql
INSERT INTO `reminders`
(userId, projectId, projectStartTime, reminderType, reminderTime, reminderContent, status, createdAt, updatedAt)
VALUES
(1, 100, DATE_ADD(NOW(), INTERVAL 1 DAY), 'start', DATE_ADD(NOW(), INTERVAL 1 MINUTE), '测试提醒', 1, NOW(), NOW());
```

3. **观察日志**：1分钟内不应出现 `[Reminder] 发送失败` 报错；
   - 若报 `43101 用户未授权`：说明该用户没有授权额度（前端授权链路问题或额度已消耗），属预期兜底；

4. **验证状态流转**：`SELECT status FROM reminders WHERE id = ...` 应为 2；
5. **验证幂等**：并发场景由条件更新兜底，同一轮不会重复发送同一条；手动 `UPDATE reminders SET status=1` 且 reminderTime 已过的记录，下一轮会重发一次（重置即重发语义）。

## 八、风险与注意事项

| 风险             | 说明                                                                                                                                                                                                             |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 微信授权额度     | 订阅消息一次授权一条。存表记录默认用户已授权；若前端漏弹授权仍存表（前端逻辑漏洞），发送会报 43101 并置3，属预期兜底而非系统 bug                                                                                 |
| 模板字段         | 5.1 示例的 `thing1`/`time2` 字段名是占位，**须按小程序后台实际申请的模板字段调整**，否则发送报 47001；thing 限20字符、time 有固定格式要求                                                                        |
| token 竞争       | `getWxAccessToken` 的单飞 Promise 在 login.js 模块级实现，导出后多处共用同一实例，无重复获取问题；token 失效由发送处 40001/42001 分支兜底                                                                        |
| openld           | 历史拼写笔误，登录链路存的就是 openid，数据正确；不改表，代码照用                                                                                                                                                |
| 表名/时区        | 表名以实际建表为准；服务器时区为 Asia/Shanghai，`reminderTime` 为 DATE 类型经 Sequelize 存取，造数测试时注意时区偏差                                                                                             |
| 订阅接口隐含问题 | `reminder.js` 中 `...req.body` 直接展开建记录：前端传 `id` 等字段会被透传写入；且未校验 `reminderTime` 须晚于当前时间、早于 `projectStartTime`。建议后续改为显式字段赋值并补校验（与定时任务无耦合，可另行处理） |
| 风暴场景         | 单轮 limit 100 + 30秒一轮，即使大量提醒同时到期也会分批消化，不会压垮 DB                                                                                                                                         |
