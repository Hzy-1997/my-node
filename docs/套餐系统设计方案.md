# 套餐系统设计方案

## 一、设计背景与目标

### 1.1 现状分析

当前系统已存在以下业务模块：

- **酒店模块**：`Hotel` → `RoomType` → `RoomPackage` → `RoomDatePrice`
- **票务模块**：`Ticket` → `PriceRule` → `TicketDatePrice` / `Seat`
- **订单模块**：`Order`（单一订单结构）

现有 `RoomPackage` 强绑定在酒店房型下，只能做纯酒店套餐，**无法支持跨业务组合**（如酒店+门票、门票+SPA）。

### 1.2 设计目标

- 支持**任意业务组合**套餐（酒店+门票、门票+观光车、酒店+门票+餐饮等）
- 套餐作为**独立产品**售卖，不依赖进入酒店/票务详情页
- **库存共用底层库存**，卖套餐直接扣 `RoomDatePrice` / `TicketDatePrice` 的库存，不另起库存池
- 每个套餐分组有且仅有**1个主产品**（酒店套餐主产品为酒店房型，门票套餐主产品为门票），日期和库存由主产品驱动
- 支持**限购数量**（营销限量，如"仅限50份"），但不创建独立库存表
- 子订单逐个核销，套餐是整体产品，核销任意一项后不可退款

### 1.3 套餐业务模式

| 模式     | 主产品   | 附带品               | 日期选择                                   | 示例                                        |
| -------- | -------- | -------------------- | ------------------------------------------ | ------------------------------------------- |
| 酒店套餐 | 酒店房型 | 门票、观光车、早餐等 | 用户选入住/离店日期，门票游玩日期=入住日期 | "五一住宿套餐"：豪华大床房1晚 + 景区门票2张 |
| 门票套餐 | 门票     | 观光车、小吃券等     | 用户选游玩日期                             | "观光特惠套餐"：景区门票1张 + 观光车票1张   |

> **注意**：不存在"买门票带酒店"的模式，酒店只能作为主产品出现

### 1.4 与当前仓库实现的关系（落地对照）

本仓库已具备：**套餐商品模型**、**显式外键的 `package_items` / `package_order_details`**、**集中关联**（见 `models/associations.js`）、**后台套餐 CRUD 路由**（`routes/managementSystem/comboRouter/combo.js`）。下列与设计初稿不一致或尚未完成的部分，已在后文章节中改为「以代码为准」或单独标注为待迁移。

| 能力 | 文档原述 | 仓库现状 |
| ---- | -------- | -------- |
| 套餐日历价 / 规则表维度 | `packageId` + `groupId` | 已改为挂 **`package_items.id`**（字段 `package_item_id`），便于「一行主产品 SKU」对应一套日历价 |
| `package_price_rules` | 含 `startDate` / `endDate` / `status` | 模型仅 **`packageItemId` + `ruleConfig`（JSON）**，日期段等可放在 JSON 内 |
| `orders` 扩展（方案 A） | `orderType`、`packageId`、`checkInDate` 等 | **`models/orderModel/index.js` 中尚未定义**，需迁移后再与第六节示例一致 |
| 用户侧下单 / 支付 / 库存事务 | 流程与示例服务 | **未检索到独立 `packageOrderService`**；支付仍以票务为主（如 `routes/managementSystem/payment/`），套餐下单需按第五节在业务层补齐 |
| 后台 `createTicketPriceRule` | — | `combo.js` 中函数名/引用为占位，应改为 `PackageDatePrice` / `PackagePriceRule` 创建逻辑 |

## 二、核心架构

### 2.1 架构图

```
┌─────────────────────────────────────────────────────────────┐
│                    ProductPackage                            │
│                   （套餐产品主表）                            │
│  - 基础信息：名称、类型、售价、封面、标签                     │
│  - 销售配置：独立售卖 / 搭配主产品                            │
│  - 库存：共用底层库存 + 限购数量（maxSaleNum）               │
│  - 日期：由主产品驱动（酒店→入住日期，门票→游玩日期）         │
└─────────────────────────────────────────────────────────────┘
                              │
        ┌─────────────────────┼─────────────────────┐
        ▼                     ▼                     ▼
┌───────────────┐    ┌───────────────┐    ┌───────────────┐
│ PackageItem 1 │    │ PackageItem 2 │    │ PackageItem N │
│ ★主产品       │    │  附带品        │    │  附带品       │
│  酒店房型      │    │   门票        │    │   观光车       │
│  (1晚住宿)    │    │  (2张票)      │     │  (1张票)      │
│  isPrimary=1  │    │  isPrimary=0  │    │  isPrimary=0  │
│  roomPackageId│    │  ticketId     │    │  ticketId     │
└───────┬───────┘    └───────┬───────┘    └───────┬───────┘

┌───────────────┐    ┌───────────────┐    ┌───────────────┐
│  RoomPackage  │    │    Ticket     │    │    Ticket     │
│ RoomDatePrice │    │  PriceRule    │    │  PriceRule    │
│  (共用库存)    │    │TicketDatePrice│    │TicketDatePrice│
│               │    │  (共用库存)   │     │  (共用库存)   │
└───────────────┘    └───────────────┘    └───────────────┘
```

**关联关系说明：**

- **酒店子项**：`package_items.room_package_id` → `room_packages.id` → `room_date_prices`（通过 `roomPackageId` 查库存）
- **门票子项**：`package_items.ticket_id` → `tickets.id`，`package_items.ticket_price_rule_id` → `price_rules.id` → `ticket_date_prices`（通过 `priceRuleId` 查库存）

**库存扣减示意：**

```
卖1份"五一住宿套餐"（豪华大床房1晚 + 景区门票2张）：

RoomDatePrice  → availableStock -= 1   ← 共用库存，单独卖房也扣这里
  查询条件：room_package_id = package_items.room_package_id

TicketDatePrice → availableStock -= 2   ← 共用库存，单独卖票也扣这里
  查询条件：price_rule_id = package_items.ticket_price_rule_id

ProductPackage  → soldStock += 1        ← 仅记录已售份数，不独立管库存
```

## 三、数据库设计

> **总共需要 5 张新表 + 1 张改造现有表**（方案A）或 **5 张新表 + 1 张新订单表**（方案B）

### 3.1 套餐主表：`product_packages`

**用途**：定义一个套餐产品的基本信息。相当于商品详情页上展示的内容。

**举例**：就像餐厅菜单上的"超值双人套餐 ¥469"这一行，告诉你叫什么、卖多少钱、包含什么。

| 字段名         | 类型          | 必填 | 默认值 | 说明                                                |
| -------------- | ------------- | ---- | ------ | --------------------------------------------------- |
| `id`           | INT           | 是   | auto   | 主键，自增                                          |
| `name`         | VARCHAR(100)  | 是   | -      | 套餐名称，如"五一游玩套餐"                          |
| `subTitle`     | VARCHAR(200)  | 否   | -      | 副标题/宣传语                                       |
| `type`         | TINYINT       | 是   | 1      | 套餐类型：1=酒店套餐 2=游玩套餐 3=赛事套餐 4=自定义 |
| `category`     | VARCHAR(50)   | 否   | -      | 自定义分类标签（如"超值特惠"、"限时抢购"）          |
| `coverImage`   | VARCHAR(500)  | 否   | -      | 封面图URL                                           |
| `bannerImages` | JSON          | 否   | -      | 轮播图数组                                          |
| `marketPrice`  | DECIMAL(10,2) | 是   | 0.00   | 市场价（划线价，展示"省了多少钱"）                  |
| `minPrice`     | DECIMAL(10,2) | 是   | 0.00   | 最低价（冗余，从 package_date_prices 取 MIN）       |
| `maxPrice`     | DECIMAL(10,2) | 是   | 0.00   | 最高价（冗余，从 package_date_prices 取 MAX）       |
| `soldStock`    | INT           | 是   | 0      | 已售份数（仅统计用，不控制库存）                    |
| `maxSaleNum`   | INT           | 是   | 0      | 总限量（0=不限量，如"全城仅限50份"）                |
| `maxBuyNum`    | INT           | 是   | 0      | 每单限购（0=不限量，如"每人限购3份"）               |
| `saleMode`     | TINYINT       | 是   | 1      | 销售方式：1=独立售卖 2=必须搭配主产品               |
| `startDate`    | DATE          | 否   | -      | 售卖开始日期                                        |
| `endDate`      | DATE          | 否   | -      | 售卖结束日期                                        |
| `tags`         | JSON          | 否   | -      | 标签数组，如["立即确认","特惠套餐"]                 |
| `includes`     | TEXT          | 否   | -      | 套餐包含权益文本描述                                |
| `refundRule`   | TEXT          | 否   | -      | 退订规则说明                                        |
| `useRule`      | TEXT          | 否   | -      | 使用规则说明                                        |
| `sortOrder`    | INT           | 是   | 0      | 排序权重，越大越靠前                                |
| `status`       | TINYINT       | 是   | 1      | 状态：1=上架 2=下架 3=售罄                          |
| `createdAt`    | DATETIME      | 是   | NOW    | 创建时间（Sequelize `timestamps`，库表多为 `created_at`） |
| `updatedAt`    | DATETIME      | 是   | NOW    | 更新时间                                            |

**索引：**

```sql
INDEX `idx_type_status` (`type`, `status`)
INDEX `idx_category` (`category`)
INDEX `idx_date_range` (`startDate`, `endDate`)
INDEX `idx_sort` (`sortOrder` DESC)
```

### 3.2 套餐明细表：`package_items`

**用途**：记录一个套餐里包含了哪些东西，每个东西多少数量。这是**关联底层酒店/票务的关键表**。

**关联方式**：通过**显式外键**关联，而非 `bizType + bizId` 软关联：

- **酒店子项**：`room_package_id` 外键关联 `room_packages` 表
- **门票子项**：`ticket_id` 外键关联 `tickets` 表，`ticket_price_rule_id` 外键关联 `price_rules` 表（用于查每日库存）

**为什么不用 `bizType + bizId`？**

1. **关联路径不同**：酒店通过 `roomPackageId` 查 `RoomDatePrice`，门票通过 `priceRuleId` 查 `TicketDatePrice`，统一用 `bizId` 无法表达这种差异
2. **外键约束**：显式外键可在数据库层面保证数据一致性，删除 `RoomPackage` 时会自动处理关联的 `package_items`
3. **联表查询**：可通过 Sequelize `include` 直接联查关联对象，无需手写条件分支
4. **避免Bug**：原设计中用 `ticketId` 查 `TicketDatePrice` 是错误的（`TicketDatePrice` 的外键是 `priceRuleId`）

**字段：**

| 字段名              | 类型          | 必填 | 默认值 | 说明                                                                               |
| ------------------- | ------------- | ---- | ------ | ---------------------------------------------------------------------------------- |
| `id`                | INT           | 是   | auto   | 主键，自增                                                                         |
| `packageId`         | INT           | 是   | -      | 关联套餐主表ID                                                                     |
| `groupId`           | INT           | 是   | -      | 分组ID：同一groupId下有1个主产品和若干附带品，用户下单时选一个组                   |
| `isPrimary`         | TINYINT       | 是   | 0      | 是否主产品：1=主产品 0=附带品（每组必须有且仅有1个主产品）                         |
| `itemType`          | TINYINT       | 是   | 1      | 子项类型：1=酒店房型 2=门票 3=其他                                                 |
| `roomPackageId`     | INT           | 否   | NULL   | 关联酒店房型套餐ID（itemType=1时必填），外键→room_packages.id                      |
| `ticketId`          | INT           | 否   | NULL   | 关联门票ID（itemType=2时必填），外键→tickets.id                                    |
| `ticketPriceRuleId` | INT           | 否   | NULL   | 关联门票价格规则ID（itemType=2时必填），外键→price_rules.id，用于查TicketDatePrice |
| `itemName`          | VARCHAR(100)  | 否   | -      | 显示名称（冗余，如"豪华大床房"）                                                   |
| `quantity`          | INT           | 是   | 1      | 包含数量（如2张票、1晚住宿）                                                       |
| `unitPrice`         | DECIMAL(10,2) | 否   | 0.00   | 该项参考原价（用于展示优惠力度，实际扣库存以底层价格为准）                         |
| `useDateType`       | TINYINT       | 是   | 1      | 使用日期类型：1=跟随主产品入住日期 2=跟随主产品游玩日期 3=固定日期 4=购买后N天内   |
| `useDateOffset`     | INT           | 否   | 0      | 日期偏移天数（如门票在入住后第2天使用则填2，仅useDateType=1时有效）                |
| `useDateValue`      | VARCHAR(50)   | 否   | -      | 日期值（固定日期时填具体日期，N天内填天数）                                        |
| `description`       | VARCHAR(255)  | 否   | -      | 该项说明（如"含双早"、"不限时"）                                                   |
| `icon`              | VARCHAR(100)  | 否   | -      | 权益图标标识（如"breakfast"、"ticket"）                                            |
| `sortOrder`         | INT           | 是   | 0      | 排序                                                                               |
| `createdAt`         | DATE          | 是   | NOW    | 创建时间                                                                           |

**举例**：

| isPrimary | itemType | roomPackageId | ticketId | ticketPriceRuleId | itemName     | quantity | 含义                          |
| --------- | -------- | ------------- | -------- | ----------------- | ------------ | -------- | ----------------------------- |
| ★1        | 1        | 5             | NULL     | NULL              | 豪华大床房   | 1        | 主产品：1晚住宿，日期由它定   |
| 0         | 2        | NULL          | 12       | 8                 | 景区观光缆车 | 2        | 附带品：2张票，跟随主产品日期 |
| 0         | 2        | NULL          | 15       | 10                | 电影票       | 2        | 附带品：上午场+下午场各1张    |

**库存查询路径：**

```javascript
// 酒店库存查询
RoomDatePrice.findOne({
  where: { roomPackageId: item.roomPackageId, date },
});

// 门票库存查询（修正：用 priceRuleId 查，不是 ticketId）
TicketDatePrice.findOne({
  where: { priceRuleId: item.ticketPriceRuleId, date },
});
```

**索引：**

```sql
INDEX `idx_package_id` (`packageId`)
INDEX `idx_group_id` (`packageId`, `groupId`)
INDEX `idx_room_package` (`roomPackageId`)
INDEX `idx_ticket` (`ticketId`)
INDEX `idx_ticket_price_rule` (`ticketPriceRuleId`)
INDEX `idx_primary` (`packageId`, `isPrimary`)
```

### 3.3 订单表设计（两种方案）

> 下面给出两种订单方案，请根据实际情况选择。

---

#### 方案A：复用现有 `orders` 表（推荐）

**思路**：在现有 `orders` 表上加 `orderType` 字段区分票务/套餐，套餐特有字段也加到这张表里。

> **仓库状态**：当前 `orders` 模型定义见 `models/orderModel/index.js`，**尚未包含**下表中的 `orderType`、`packageId`、`checkInDate` 等字段；上线套餐订单前需编写 Sequelize migration 与模型同步更新，并梳理票务创建订单处对 `allowNull`、校验逻辑的兼容性（例如套餐订单 `seat`、实名制字段是否放宽或填占位值）。

**verifyStatus 不冲突**：套餐只要核销了一个子项，主订单 verifyStatus 就改为"已核销(2)"，和票务的含义一致。具体的哪些子项已核销/未核销，在 `package_order_details` 表里查看。

**优势**：订单列表统一管理、支付/退款逻辑复用、前端不用区分两套订单页面

**劣势**：表字段会变多，部分字段对票务/套餐只有一边有意义

**需要给现有 `orders` 表新增的字段：**

| 字段名         | 类型        | 必填 | 默认值 | 说明                                            |
| -------------- | ----------- | ---- | ------ | ----------------------------------------------- |
| `orderType`    | TINYINT     | 是   | 1      | 订单类型：1=票务订单（原有） 2=套餐订单（新增） |
| `packageId`    | INT         | 否   | -      | 套餐ID（orderType=2时必填）                     |
| `checkInDate`  | DATE        | 否   | -      | 入住日期（酒店类套餐）                          |
| `checkOutDate` | DATE        | 否   | -      | 离店日期                                        |
| `payChannel`   | VARCHAR(20) | 否   | -      | 支付渠道：alipay / wechat                       |
| `expireTime`   | DATETIME    | 否   | -      | 订单过期时间（15分钟未支付自动取消）            |

**现有字段复用对照：**

| 现有字段        | 票务订单含义 | 套餐订单含义       | 说明                                    |
| --------------- | ------------ | ------------------ | --------------------------------------- |
| `orderNumber`   | 票务订单号   | 套餐订单号         | PKG前缀区分                             |
| `title`         | 票名称       | 套餐名称           |                                         |
| `ticketType`    | 票种         | 套餐类型           |                                         |
| `ticketPrice`   | 票价         | 套餐原价（划线价） |                                         |
| `goodsId`       | 票务ID       | 套餐ID             | 和 packageId 相同                       |
| `buyNum`        | 购票数量     | 购买份数           |                                         |
| `orderAmount`   | 订单金额     | 实付金额           |                                         |
| `orderStatus`   | 订单状态     | 订单状态           | 1待支付→2待核销→3已取消→4已完成→5已退款 |
| `verifyStatus`  | 核销状态     | 核销状态           | 1未核销→2已核销（核销一个就算已核销）   |
| `playDate`      | 游玩日期     | 游玩/入住日期      |                                         |
| `userName`      | 用户姓名     | 联系人姓名         |                                         |
| `userPhone`     | 用户电话     | 联系人电话         |                                         |
| `userIdCard`    | 身份证号     | 联系人身份证       |                                         |
| `seat`          | 座位         | 套餐不使用         | 套餐订单填空字符串                      |
| `alipayTradeNo` | 支付宝流水号 | 支付宝流水号       | 通用                                    |
| `refundAmount`  | 退款金额     | 退款金额           | 通用                                    |

#### 方案B：独立套餐订单表 `package_orders`

**思路**：套餐订单单独建表，和现有 `orders` 表完全独立。

**优势**：字段干净，套餐特有字段不用塞到通用表里；票务和套餐互不影响

**劣势**：两套订单列表、两套支付逻辑、前端需要区分订单页面

| 字段名          | 类型          | 必填 | 默认值 | 说明                                                   |

## 五、库存设计

### 5.1 库存共用原理

套餐不创建独立库存池，直接扣减底层业务表的库存：

- **酒店子项**：扣 `RoomDatePrice.availableStock`
- **门票子项**：扣 `TicketDatePrice.availableStock`

这样单独购买酒店/门票和购买套餐走的是同一套库存，不会出现超卖。

### 5.2 库存字段说明

| 表名              | 库存字段         | 说明                       |
| ----------------- | ---------------- | -------------------------- |
| `RoomDatePrice`   | `availableStock` | 可售库存（共用）           |
| `TicketDatePrice` | `availableStock` | 可售库存（共用）           |
| `ProductPackage`  | `soldStock`      | 已售份数（仅统计，不控制） |

### 5.3 库存校验流程

```
┌──────────────────────────────────────────────────┐
│              套餐下单库存流程                      │
│                                                  │
│  1. 校验限购数量（maxSaleNum）                    │
│       ↓                                          │
│  2. 找到主产品（isPrimary=1），确定日期            │
│       ↓                                          │
│  3. 实时校验所有 item 的底层库存                   │
│     - 酒店房型 → RoomDatePrice.availableStock     │
│       查询条件：roomPackageId = item.roomPackageId │
│     - 门票     → TicketDatePrice.availableStock   │
│       查询条件：priceRuleId = item.ticketPriceRuleId│
│       ↓                                          │
│  4. 事务内原子扣减所有底层库存 + 套餐soldStock     │
│       ↓                                          │
│  5. 支付超时/取消 → 事务回滚或补偿释放库存         │
└──────────────────────────────────────────────────┘
```

**关键：步骤4必须在同一个数据库事务内完成，防止部分扣减导致数据不一致。**

### 5.4 库存校验实现

```javascript
async function checkPackageStock(
  package,
  items,
  checkIn,
  checkOut,
  playDate,
  buyNum,
) {
  // 1. 校验限购数量
  if (
    package.maxSaleNum > 0 &&
    package.soldStock + buyNum > package.maxSaleNum
  ) {
    return { available: false, reason: "套餐已售罄" };
  }

  // 2. 校验每个 item 的底层库存
  for (const item of items) {
    const needStock = buyNum * item.quantity;

    if (item.itemType === 1 && item.roomPackageId) {
      // 酒店房型：通过 roomPackageId 查 RoomDatePrice
      const dates = generateDateRange(checkIn, checkOut);
      for (const date of dates) {
        const stock = await RoomDatePrice.findOne({
          where: { roomPackageId: item.roomPackageId, date },
        });
        if (!stock || stock.availableStock < needStock) {
          return {
            available: false,
            reason: `${item.itemName} ${date} 库存不足`,
          };
        }
      }
    } else if (item.itemType === 2 && item.ticketPriceRuleId) {
      // 门票：通过 ticketPriceRuleId 查 TicketDatePrice
      const ticketPlayDate = item.useDateType === 1 ? checkIn : playDate;
      const stock = await TicketDatePrice.findOne({
        where: { priceRuleId: item.ticketPriceRuleId, date: ticketPlayDate },
      });
      if (!stock || stock.availableStock < needStock) {
        return { available: false, reason: `${item.itemName} 库存不足` };
      }
    }
  }

  return { available: true };
}
```

### 5.5 库存扣减实现（事务内原子操作）

```javascript
async function deductPackageStock(
  package,
  items,
  checkIn,
  checkOut,
  playDate,
  buyNum,
  transaction,
) {
  // 1. 扣减套餐已售数量
  await ProductPackage.increment("soldStock", {
    by: buyNum,
    where: { id: package.id },
    transaction,
  });

  // 2. 扣减每个 item 的底层库存（同一事务）
  for (const item of items) {
    const needStock = buyNum * item.quantity;

    if (item.itemType === 1 && item.roomPackageId) {
      // 酒店房型库存扣减
      const dates = generateDateRange(checkIn, checkOut);
      for (const date of dates) {
        const affected = await RoomDatePrice.decrement("availableStock", {
          by: needStock,
          where: {
            roomPackageId: item.roomPackageId,
            date,
            availableStock: { [Op.gte]: needStock },
          },
          transaction,
        });
        if (affected[0][1] === 0) {
          throw new Error(`${item.itemName} ${date} 库存不足，扣减失败`);
        }
        await RoomDatePrice.increment("soldStock", {
          by: needStock,
          where: { roomPackageId: item.roomPackageId, date },
          transaction,
        });
      }
    } else if (item.itemType === 2 && item.ticketPriceRuleId) {
      // 门票库存扣减（修正：用 priceRuleId 查询）
      const ticketPlayDate = item.useDateType === 1 ? checkIn : playDate;
      const affected = await TicketDatePrice.decrement("availableStock", {
        by: needStock,
        where: {
          priceRuleId: item.ticketPriceRuleId,
          date: ticketPlayDate,
          availableStock: { [Op.gte]: needStock },
        },
        transaction,
      });
      if (affected[0][1] === 0) {
        throw new Error(`${item.itemName} 库存不足，扣减失败`);
      }
      await TicketDatePrice.increment("soldStock", {
        by: needStock,
        where: { priceRuleId: item.ticketPriceRuleId, date: ticketPlayDate },
        transaction,
      });
    }
  }
}
```

> **注意**：`decrement` 时加了 `availableStock >= needStock` 条件，如果影响行数为0说明并发超卖，事务会回滚。
>
> **关键修正**：门票库存查询条件从 `ticketId` 改为 `priceRuleId`，因为 `TicketDatePrice` 表的外键是 `price_rule_id`，不是 `ticket_id`。

### 5.6 库存释放（取消/退款）

```javascript
async function releasePackageStock(
  package,
  items,
  checkIn,
  checkOut,
  playDate,
  buyNum,
  transaction,
) {
  // 1. 减少套餐已售数量
  await ProductPackage.decrement("soldStock", {
    by: buyNum,
    where: { id: package.id },
    transaction,
  });

  // 2. 释放底层库存
  for (const item of items) {
    const releaseStock = buyNum * item.quantity;

    if (item.itemType === 1 && item.roomPackageId) {
      // 酒店房型库存释放
      const dates = generateDateRange(checkIn, checkOut);
      for (const date of dates) {
        await RoomDatePrice.increment("availableStock", {
          by: releaseStock,
          where: { roomPackageId: item.roomPackageId, date },
          transaction,
        });
        await RoomDatePrice.decrement("soldStock", {
          by: releaseStock,
          where: { roomPackageId: item.roomPackageId, date },
          transaction,
        });
      }
    } else if (item.itemType === 2 && item.ticketPriceRuleId) {
      // 门票库存释放（修正：用 priceRuleId）
      const ticketPlayDate = item.useDateType === 1 ? checkIn : playDate;
      await TicketDatePrice.increment("availableStock", {
        by: releaseStock,
        where: { priceRuleId: item.ticketPriceRuleId, date: ticketPlayDate },
        transaction,
      });
      await TicketDatePrice.decrement("soldStock", {
        by: releaseStock,
        where: { priceRuleId: item.ticketPriceRuleId, date: ticketPlayDate },
        transaction,
      });
    }
  }
}
```

### 5.7 并发安全：分布式锁

高并发场景下（如秒杀套餐），需加分布式锁防止超卖：

```javascript
const redisLock = async (key, ttl, fn) => {
  const lockKey = `lock:package:${key}`;
  const acquired = await redis.set(lockKey, "1", "PX", ttl, "NX");
  if (!acquired) throw new Error("系统繁忙，请稍后重试");
  try {
    return await fn();
  } finally {
    await redis.del(lockKey);
  }
};

// 使用示例
await redisLock(`stock:${packageId}:${checkIn}`, 5000, async () => {
  await sequelize.transaction(async (t) => {
    await deductPackageStock(
      package,
      items,
      checkIn,
      checkOut,
      playDate,
      buyNum,
      t,
    );
    // ... 创建订单等操作
  });
});
```

### 6.2 订单状态机

#### 主订单状态（复用 orders 表 orderStatus）

```
待支付(1) ──支付成功──▶ 待核销(2) ──全部明细核销──▶ 已完成(4)
   │                       │
   │──超时未支付──▶ 已取消(3)                     │
   │                       │
   │──用户取消────▶ 已取消(3)                     │
                           │
                           └──退款申请──▶ 已退款(5)
                               （仅全部未核销时可退）
```

#### 明细核销状态（package_order_details.verifyStatus）

```
未核销(1) ──扫码核销──▶ 已核销(2)

规则：
  - 任意一个明细核销 → 主订单 verifyStatus 更新为已核销(2)，不可退款
  - 商家扫码可查看每个明细的核销状态（哪些已核销、哪些未核销）
  - 用户端只展示自己的二维码，不关心"部分核销"概念
```

### 6.3 关键代码示例

#### 创建套餐订单

```javascript
// services/packageOrderService.js
const { sequelize } = require("../mysql/index");
const {
  ProductPackage,
  PackageItem,
  PackageDatePrice,
  Order,
  PackageOrderDetail,
  RoomDatePrice,
  TicketDatePrice,
} = require("../models/Summary");
const { Op } = require("sequelize");

class PackageOrderService {
  async createOrder(params) {
    const {
      packageId,
      buyNum,
      checkIn,
      checkOut,
      playDate,
      memberId,
      contactInfo,
    } = params;

    return await sequelize.transaction(async (t) => {
      // 1. 查询套餐及明细（利用 Sequelize 关联自动联查）
      const package = await ProductPackage.findByPk(packageId, {
        include: [
          {
            model: PackageItem,
            as: "items",
            include: [
              { model: RoomPackage, as: "roomPackage" }, // 酒店房型关联
              { model: Ticket, as: "ticket" }, // 门票关联
              { model: PriceRule, as: "ticketPriceRule" }, // 门票价格规则关联
            ],
          },
        ],
        transaction: t,
        lock: t.LOCK.UPDATE,
      });

      if (!package || package.status !== 1) {
        throw new Error("套餐不存在或已下架");
      }

      // 2. 校验限购数量
      if (
        package.maxSaleNum > 0 &&
        package.soldStock + buyNum > package.maxSaleNum
      ) {
        throw new Error("该套餐已售罄");
      }

      // 3. 找到主产品，确定日期
      const primaryItem = package.items.find((item) => item.isPrimary === 1);
      if (!primaryItem) {
        throw new Error("套餐缺少主产品");
      }

      // 4. 校验并扣减底层库存（同一事务内原子操作）
      await this._deductBizStock(
        package.items,
        checkIn,
        checkOut,
        playDate,
        buyNum,
        t,
      );

      // 5. 扣减套餐已售数量（与第4步二选一聚合：也可放入 _deductBizStock 同一函数，避免重复维护）
      await ProductPackage.increment("soldStock", {
        by: buyNum,
        where: { id: package.id },
        transaction: t,
      });

      // 6. 生成订单号
      const orderNumber = this._generateOrderNumber();

      // 7. 创建主订单（复用现有 Order 表）
      // 日历价挂在主产品对应的 package_items 行上（packageItemId），不是 packageId
      const datePrice = await PackageDatePrice.findOne({
        where: {
          packageItemId: primaryItem.id,
          date: primaryItem.itemType === 1 ? checkIn : playDate,
          status: 1,
        },
        transaction: t,
      });

      if (!datePrice) {
        throw new Error("所选日期暂不可购买");
      }

      const totalAmount = datePrice.price * buyNum;
      const order = await Order.create(
        {
          orderNumber,
          memberId,
          orderType: 2,
          title: package.name,
          ticketType: package.type.toString(),
          ticketPrice: package.marketPrice.toString(),
          goodsId: packageId,
          buyNum: buyNum.toString(),
          orderAmount: totalAmount.toString(),
          orderStatus: 1,
          verifyStatus: 1,
          playDate: primaryItem.itemType === 1 ? checkIn : playDate,
          checkInDate: primaryItem.itemType === 1 ? checkIn : null,
          checkOutDate: primaryItem.itemType === 1 ? checkOut : null,
          ...contactInfo,
          expireTime: new Date(Date.now() + 15 * 60 * 1000),
        },
        { transaction: t },
      );

      // 8. 创建订单明细（每个可核销项独立核销码）
      for (const item of package.items) {
        let useDate, useEndDate;
        if (item.itemType === 1) {
          useDate = checkIn;
          useEndDate = checkOut;
        } else {
          useDate = item.useDateType === 1 ? checkIn : playDate;
          useEndDate = null;
        }

        await PackageOrderDetail.create(
          {
            orderNumber,
            packageId: package.id,
            groupId: item.groupId,
            isPrimary: item.isPrimary,
            itemType: item.itemType,
            roomPackageId: item.roomPackageId,
            ticketId: item.ticketId,
            ticketPriceRuleId: item.ticketPriceRuleId,
            itemName: item.itemName,
            quantity: item.quantity * buyNum,
            unitPrice: item.unitPrice,
            totalPrice: item.unitPrice * item.quantity * buyNum,
            useDate,
            useEndDate,
            verifyCode: this._generateVerifyCode(),
            verifyStatus: 1,
          },
          { transaction: t },
        );
      }

      return { order };
    });
  }

  async _deductBizStock(
    items,
    checkIn,
    checkOut,
    playDate,
    buyNum,
    transaction,
  ) {
    for (const item of items) {
      const needStock = buyNum * item.quantity;

      if (item.itemType === 1 && item.roomPackageId) {
        // 酒店房型库存扣减
        const dates = generateDateRange(checkIn, checkOut);
        for (const date of dates) {
          const affected = await RoomDatePrice.decrement("availableStock", {
            by: needStock,
            where: {
              roomPackageId: item.roomPackageId,
              date,
              availableStock: { [Op.gte]: needStock },
            },
            transaction,
          });
          if (affected[0][1] === 0) {
            throw new Error(`${item.itemName} ${date} 库存不足`);
          }
          await RoomDatePrice.increment("soldStock", {
            by: needStock,
            where: { roomPackageId: item.roomPackageId, date },
            transaction,
          });
        }
      } else if (item.itemType === 2 && item.ticketPriceRuleId) {
        // 门票库存扣减（修正：用 priceRuleId 查询）
        const ticketPlayDate = item.useDateType === 1 ? checkIn : playDate;
        const affected = await TicketDatePrice.decrement("availableStock", {
          by: needStock,
          where: {
            priceRuleId: item.ticketPriceRuleId,
            date: ticketPlayDate,
            availableStock: { [Op.gte]: needStock },
          },
          transaction,
        });
        if (affected[0][1] === 0) {
          throw new Error(`${item.itemName} 库存不足`);
        }
        await TicketDatePrice.increment("soldStock", {
          by: needStock,
          where: { priceRuleId: item.ticketPriceRuleId, date: ticketPlayDate },
          transaction,
        });
      }
    }
  }

  _generateOrderNumber() {
    const date = new Date().toISOString().slice(0, 10).replace(/-/g, "");
    const random = Math.random().toString(36).substring(2, 10).toUpperCase();
    return `PKG${date}${random}`;
  }

  _generateVerifyCode() {
    return Math.random().toString(36).substring(2, 10).toUpperCase();
  }
}

module.exports = { PackageOrderService };
```

## 七、数据库迁移方案

### 7.1 迁移背景

将 `package_items` 表从 `bizType + bizId` 软关联改造为显式外键关联。

### 7.2 迁移步骤

#### 步骤1：添加新字段

```sql
-- 添加显式外键字段
ALTER TABLE package_items
  ADD COLUMN item_type TINYINT NOT NULL DEFAULT 1 COMMENT '子项类型：1=酒店房型 2=门票' AFTER is_primary,
  ADD COLUMN room_package_id INT NULL COMMENT '关联酒店房型套餐ID' AFTER item_type,
  ADD COLUMN ticket_id INT NULL COMMENT '关联门票ID' AFTER room_package_id,
  ADD COLUMN ticket_price_rule_id INT NULL COMMENT '关联门票价格规则ID' AFTER ticket_id,
  ADD COLUMN item_name VARCHAR(100) NULL COMMENT '显示名称' AFTER ticket_price_rule_id;

-- 添加外键约束
ALTER TABLE package_items
  ADD CONSTRAINT fk_package_items_room_package
    FOREIGN KEY (room_package_id) REFERENCES room_packages(id)
    ON DELETE SET NULL ON UPDATE CASCADE,
  ADD CONSTRAINT fk_package_items_ticket
    FOREIGN KEY (ticket_id) REFERENCES tickets(id)
    ON DELETE SET NULL ON UPDATE CASCADE,
  ADD CONSTRAINT fk_package_items_price_rule
    FOREIGN KEY (ticket_price_rule_id) REFERENCES price_rules(id)
    ON DELETE SET NULL ON UPDATE CASCADE;

-- 添加新索引
CREATE INDEX idx_room_package ON package_items(room_package_id);
CREATE INDEX idx_ticket ON package_items(ticket_id);
CREATE INDEX idx_ticket_price_rule ON package_items(ticket_price_rule_id);
```

#### 步骤2：迁移数据

```sql
-- 迁移酒店数据：biz_type='hotel' → item_type=1, room_package_id=biz_id
UPDATE package_items
SET item_type = 1,
    room_package_id = biz_id,
    item_name = biz_name
WHERE biz_type = 'hotel';

-- 迁移门票数据：biz_type='ticket' → item_type=2, ticket_id=biz_id
-- 注意：ticket_price_rule_id 需要额外查询 price_rules 表获取
UPDATE package_items pi
SET item_type = 2,
    ticket_id = pi.biz_id,
    item_name = pi.biz_name
WHERE pi.biz_type = 'ticket';

-- 补充 ticket_price_rule_id（取该 ticket 的第一个启用中的价格规则）
UPDATE package_items pi
SET pi.ticket_price_rule_id = (
  SELECT pr.id FROM price_rules pr
  WHERE pr.ticket_id = pi.ticket_id AND pr.status = 1
  ORDER BY pr.id ASC LIMIT 1
)
WHERE pi.item_type = 2 AND pi.ticket_id IS NOT NULL;
```

#### 步骤3：删除旧字段

```sql
-- 删除旧字段
ALTER TABLE package_items
  DROP COLUMN biz_type,
  DROP COLUMN biz_id,
  DROP COLUMN biz_name;

-- 删除旧索引
DROP INDEX idx_biz ON package_items;
```

### 7.3 回滚方案

```sql
-- 回滚：恢复旧字段
ALTER TABLE package_items
  ADD COLUMN biz_type VARCHAR(20) NULL,
  ADD COLUMN biz_id INT NULL,
  ADD COLUMN biz_name VARCHAR(100) NULL;

-- 回滚：恢复数据
UPDATE package_items
SET biz_type = CASE WHEN item_type = 1 THEN 'hotel' WHEN item_type = 2 THEN 'ticket' END,
    biz_id = COALESCE(room_package_id, ticket_id),
    biz_name = item_name;

-- 回滚：删除新字段
ALTER TABLE package_items
  DROP COLUMN item_type,
  DROP COLUMN room_package_id,
  DROP COLUMN ticket_id,
  DROP COLUMN ticket_price_rule_id,
  DROP COLUMN item_name;
```

## 九、关键变更总结

| 变更项               | 原设计                       | 新设计                                         | 原因                                            |
| -------------------- | ---------------------------- | ---------------------------------------------- | ----------------------------------------------- |
| 酒店关联字段         | `bizType='hotel', bizId=5`   | `itemType=1, roomPackageId=5`                  | 显式外键，有数据库约束                          |
| 门票关联字段         | `bizType='ticket', bizId=12` | `itemType=2, ticketId=12, ticketPriceRuleId=8` | 需要 priceRuleId 才能查库存                     |
| 库存查询条件（酒店） | `roomPackageId = item.bizId` | `roomPackageId = item.roomPackageId`           | 字段名明确                                      |
| 库存查询条件（门票） | `ticketId = item.bizId` ❌   | `priceRuleId = item.ticketPriceRuleId` ✅      | 修正Bug：`TicketDatePrice` 外键是 `priceRuleId` |
| 数据一致性           | 无约束                       | 外键约束 + ON DELETE SET NULL                  | 删除酒店/门票时自动处理                         |
| 联表查询             | 手写分支                     | Sequelize `include`                            | 代码更简洁，不易出错                            |
| 套餐日历价归属       | `product_packages` 直连 `package_date_prices` | 挂在 **`package_items`**（`package_item_id`） | 与分组主 SKU 一致，已实现于仓库               |
| 订单表方案 A         | 文档字段齐全                 | **迁移与模型待补**                             | 见 3.3 节仓库状态说明                           |

## 十、后续实现建议（结合现有支付与秒杀）

1. **订单扩展**：新增 `orderType` 后，在现有支付宝/微信回调与 `routes/managementSystem/payment/` 下分支处理 `orderType === 2`，避免把套餐误走纯票务核销逻辑。
2. **库存**：第五节事务扣减与现有 `RoomDatePrice` / `TicketDatePrice` 模型一致即可复用；若存在秒杀链路（如 `seckillPayment.js`），需明确套餐是否参与秒杀：**共用底层库存时**，应复用同一套预占/释放语义，或显式禁止「单票秒杀 + 套餐直购」并发竞态未处理的路径。
3. **核销**：`package_order_details.verifyCode` 需在管理端核销接口中按行更新，并同步更新主单 `orders.verifyStatus`（字段存在后）。
4. **后台补全**：`combo.js` 中日期价、规则创建接口应对齐 `PackageDatePrice` / `PackagePriceRule` 模型字段（`packageItemId`），并校验目标 `package_item` 属于当前套餐且 `isPrimary === 1`（若业务规定仅主档可报价）。
